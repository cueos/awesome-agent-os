# Selection rules

## Scope

The list covers personal agents for ongoing tasks, companion chatbots for
recurring conversation and characters, and open source building blocks for
agents. Products belong in the first two sections; reusable components belong
under the need they serve.

A personal agent can have a character, and a companion can have tools. Group
each entry by its main purpose. A model, a generic chat interface, or an API
wrapper needs a distinct capability within this scope to earn an entry.
Papers, courses, and demo notebooks belong elsewhere.

## Evidence

An entry should show use by people beyond its authors. Stars are one weak
signal; a small project serving a distinct need can be more useful than a
large duplicate.

For a product, link its official site or documentation, describe capabilities
supported there, and identify preview or invitation limits when relevant.
Hosted and proprietary products are eligible for the product sections.

For a building block, the repository must show an open source licence, remain
unarchived, and have a push within the last year. The checker enforces activity
and reachability; those checks do not establish feature quality.

Write descriptions in plain words. Keep advertised capability, demonstrated
behaviour, and personal opinion distinct. Claims about reliability, privacy,
or comparative quality need evidence beyond a product tagline.

## Disclosure

The maintainers build Cue OS and describe it in the maintainer section.
Additions and removals use the same selection criteria, regardless of a
project's relationship to the maintainers.
